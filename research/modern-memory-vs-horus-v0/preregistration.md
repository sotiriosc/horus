# Modern memory versus Horus v0 — preregistration

Parent: `652e5e165d5be9447e1d9ecf93c641aa6091113d`.

This study compares `M`, the frozen strong modern-memory baseline, with `MH`,
the same protected framework and memory rule plus the established G2/G3
relation router and grounded Explorer. It changes no model weights, Horus
policy, threshold, or architecture and uses no Zakhor mechanism.

## Frozen conditions

Both conditions use separate authentic protected sessions with matched external
regimes and semantically identical observation schedules. Receipt identities
remain condition-local and are never copied. Both durable stores are append-only
and admit only their own authenticated publication. Retrieval is exact relation,
recent four, newest missing-consequence anchor, and deterministic recency fill to
six, in chronological prompt order.

`M` uses the active generation-2 consequence specialist, the existing joint
next-state model, and the existing mechanical Explorer. `MH` uses the same joint
model and retrieval rule plus the frozen generation-2/generation-3 pool,
relation-local rolling-six router (minimum three, lead two), and the existing
grounded Explorer policy. Problem management, scoped routes, repair recovery,
and reacquisition remain dormant unless the frozen workload legitimately
reaches their existing trigger; the harness creates no substitute trigger.

## Schedule and budget

Stage A contains 12 matched observation-controlled HOLD events:

- events 1–4: regime A / stable;
- events 5–8: regime B / change and persistence;
- fresh-process restart after event 6;
- events 9–12: regime A / restoration.

After restart and before event 7, one matched perturbation replaces the HOLD
joint parser input with a registered malformed value after the real response is
received. Both conditions must reject the batch, execute nothing, publish no
receipt or Memory, and proceed to one ordinary valid event 7 without retrying
the failed batch.

Stage B contains four autonomous decisions from each condition's authenticated
post-Stage-A state under regime A. M uses its normal mechanical choice; MH uses
its current grounded Explorer and router. No counterfactual receipt is minted.

Every ordinary or perturbation opportunity issues six M requests (three joint,
three G2) and nine MH requests (three joint, three G2, three G3). There are 17
paired opportunities and exactly **255 real model calls**, with no retries.
Temperature is zero and seed is 20260927. Runtime boundaries occur at initial
start, each regime transition, the registered restart, the perturbation-to-valid
handoff, and Stage B. No protected runtime exceeds 12 executed episodes.

## Frozen analysis

Report consequence and exact accuracy, realized consequence, adaptation and
restoration latency, false persistence, stale-history and right-memory/model-
wrong cases, invalidity, abstention, restart, calls, latency, and context tokens.
Use Stage-A windows 1–4, 5–8, and 9–12 plus worst rolling four.

Create an intervention row whenever predictions or autonomous actions differ.
For matched Stage A, `IMPROVED` means only MH is consequence-correct,
`DEGRADED` means only M is consequence-correct, otherwise `NO_CHANGE`. For
autonomous divergence, compare only realized consequences actually obtained;
no unexecuted outcome is inferred. Tag mechanisms using the requested Horus
component vocabulary.

Classification is descriptive: more degraded than improved interventions is
`HORUS_NET_HARMFUL`; both improved and degraded is `MIXED_COMPONENT_SIGNAL`;
at least one improved and no degraded is `HORUS_DISTINCTLY_USEFUL`; no improved
or degraded difference is `MODERN_BASE_SUFFICIENT`. Any protected, replay,
restart, schedule, or accounting failure makes the result `INVALID`.
