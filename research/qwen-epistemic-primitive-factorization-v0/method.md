## Exact prospective specification

Every state has one named system, two explicit builds with creation order, an explicit deployment build, two directly aligned trials with supplied finite requirement tables, and two equal-standing immutable mark assertions. This is not repository-like raw evidence. The first listed trial is the designated trial for currentness, input knownness, alternative existence and reference-completion comparison. The deployment relation selects the trial used for the operational sufficiency proposition. Assertion subjects are complete readable tuples of build, station and cycle. Their values describe mark events, not the operational input. No opaque graph or component lookup is required. A trial has reported_input, admissible_inputs, reference_input, required_results and observed_result. Every complete table has three symbolic input values and exact required outputs; no mechanical computation is requested. UNKNOWN means uncaptured, not an input token. A singleton admissible domain still determines the actual input. A concrete capture restricts possibilities to that value. The observed output must not be inverted to infer an input by presuming compliance: the measurement may violate its requirement. Every reference_input is compatible and is the first table input. Explicit reference-completion comparison is hypothetical when the actual input is unresolved; it does not claim that completion is actual.

The mark assertions are separate facts about the same system. They do not constrain any trial input. The whole package is used for final diagnosis. An incompatible pair of equal-standing immutable mark assertions makes the package contradictory even if its operational projection has a determined comparison. All trial capture/domain facts are internally consistent at every endpoint.

## Primitive scopes and gold

IDENTITY_EQUALITY: the two mark subjects name the same referent iff their complete tuples are identical; their asserted values are equal iff the supplied strings are identical. Return exactly {same_referent:boolean,equal_value:boolean}. Both fields and joint correctness are scored. Across eight endpoints each of the four Boolean combinations occurs twice. Two pairs flip only referent identity and two flip only value equality. Unequal values do not establish different identity; equal values do not establish same identity.

CURRENTNESS: whether the first trial's build equals the explicitly deployed build. Return {answer:CURRENT|NOT_CURRENT}; no defect judgment. All four pairs change only the deployment build. Both answers occur four times. One pair moves from a trial with decision-relevant unresolved input to a captured trial and therefore also changes operational sufficiency.

KNOWN_VS_UNKNOWN: whether the first trial input is uniquely fixed by its capture and admissible domain. Return {answer:KNOWN|UNKNOWN}. All four target pairs remove only a concrete capture, replacing it with UNKNOWN in a three-value domain. Mark assertions stay consistent; contradiction is never the reason for unknownness. Domain implications are licensed; output inversion is prohibited. Removing a capture introduces alternatives, and may or may not change decision sufficiency. Both labels occur four times.

CONTRADICTION: whether the two mark assertions can coexist. Return {answer:CONSISTENT|CONTRADICTORY}. Same complete subject plus unequal asserted value is contradictory; distinct subject tuples permit unequal values; duplicate agreeing assertions are consistent. Pairs separately change a value, station, build or cycle. Each such change necessarily also changes a component of IDENTITY_EQUALITY; disclose this logical coupling. Both outputs occur four times.

ALTERNATIVE_COMPLETION_EXISTENCE: whether the first trial admits an input different from its explicit reference_input after applying capture and domain. Return {answer:ALTERNATIVE_EXISTS|NO_ALTERNATIVE}. All four pairs add one input to an uncaptured singleton domain, leaving the complete contract table and observation fixed. UNKNOWN is a capture marker, so a singleton can still entail KNOWN. Accordingly all four alternative flips necessarily also flip knownness. Two pairs keep all completion comparisons alike (one all matches, one all mismatches); two introduce a completion with a different comparison outcome and therefore also change sufficiency. Both labels occur four times. This limitation on orthogonality is disclosed instead of distorting the domain semantics.

OBSERVATION_REQUIREMENT_COMPARISON: compare the first trial's exact observation with its supplied required output at reference_input. Return {answer:MATCH|MISMATCH}; no inference about final diagnosis. Each pair changes only the observation. Cases include a deployed trial, an older non-serving trial, a non-serving trial while current input is unresolved, and a package with a separate mark disagreement. This distinguishes comparison from temporal applicability and package validity. Both labels occur four times.

EVIDENCE_SUFFICIENCY: using only deployment and trial facts, is the truth of “the deployed trial observation differs from the required output for its actual input” uniquely determined? Return {answer:DETERMINATE|UNDERDETERMINED}. Enumerate inputs allowed by capture/domain; evaluate exact supplied requirement comparisons; DETERMINATE means the violation Boolean is identical across all remaining inputs. This is a narrow operational proposition, not validity of the entire evidence package or five-class diagnosis. Mark facts do not constrain trial inputs. This scope keeps every offline primitive vector defined even for a package with contradictory marks; it is not classical inference from an inconsistent total theory. Every sufficiency TARGET pair nevertheless keeps the entire state internally consistent, as required. All four have UNKNOWN and three allowed completions on both sides, and change just one non-reference requirement-table cell. They contrast all-match or all-mismatch completions with mixed outcomes, while leaving alternative existence, knownness, reference comparison and all other primitive golds unchanged. Both labels occur four times.

No primary primitive output has a classification field or final diagnostic class. The primitive question necessarily names its measured concept; the aligned state never contains gold, verdict, class, diagnostic, validity, sufficiency or compliance flags. Generic state semantics describe equality, immutable scope and domain constraints without providing the answer.

## Five-class reduction

One independent call per endpoint receives byte-identical aligned-state serialization to its primitive counterpart. Only the instruction, system message and response schema differ. No primitive question, answer, correctness, vector or summary is provided. Natural-language definitions and label order are copied exactly from the preceding completed study; the generic ontology is deliberate reuse. Return only {classification:one_of_five_labels}; no rationale is scored.

Direct reduction gold rule on the complete state, independently verified: incompatible equal-standing mark assertions -> INVALID_OR_CONTRADICTORY_EVIDENCE. Otherwise enumerate current admissible inputs using captured value/domain. If all require an output unequal to the observation -> SUPPORTED_CURRENT_DEFECT. If both matching and nonmatching completions remain -> INSUFFICIENT_EVIDENCE. If all current completions match and an explicitly older supplied build has a demonstrated mismatch for every remaining input -> HISTORICAL_DEFECT_NOT_CURRENT. Otherwise -> NO_SUPPORTED_DIAGNOSIS. A newer non-serving violation is not evidence of an older-version defect. These cases contain no additional uncertainty outside the declared finite scopes.

Reduction denominators, frozen before inference: current defect 12; no supported diagnosis 12; insufficient evidence 11; historical defect 11; contradictory evidence 10. These arise from primitive pairs without case repair for observed performance. There are 19 pairs whose diagnostic class changes and nine whose class stays constant; class-stable pairs are controls, not failed flip opportunities.

## Scoring, gates and registered interpretations

Strict JSON rejects duplicate keys, nonfinite values, wrappers and trailing prose. Full exact schema required for endpoint credit. Malformed or missing outputs get zero primary credit; no semantic repair or hidden-reasoning rescue. Identity fields score separately /8, with schema validity required; joint exact correctness determines the main endpoint gate. Other primitive outputs use their exact frozen enum strings.

For each primitive separately: endpoint /8, schema-valid /8, binary confusion counts (identity has per-field 2x2 plus joint four-combination matrix), pair pass /4, endpoint outputs, selected A->B transitions, missing/invalid outputs and coupled non-target changes. Pair pass requires both endpoints correct and selected target response changing in the registered direction; for identity use the designated field and require both full objects correct. Competence gate: >=7/8 endpoints AND >=3/4 pairs. Findings are exactly <PRIMITIVE>_COMPETENCE_ESTABLISHED or <PRIMITIVE>_COMPETENCE_NOT_ESTABLISHED. No primitive borrows another's success.

Gate finding FIVE_CLASS_REDUCTION_COMPETENCE_ESTABLISHED or FIVE_CLASS_REDUCTION_COMPETENCE_NOT_ESTABLISHED.

On diagnostic-flip pairs, reduction sensitivity pass requires both endpoints correct and the exact expected label transition. On class-stable pairs, separately report both-endpoint-correct class retention. Also report all-pair exact pass /4 within family, without calling class-stable retention a flip. For each family report a 2x2 endpoint table of primitive correctness versus reduction correctness, plus a 2x2 pair table of primitive pair pass versus reduction exact-pair pass.
