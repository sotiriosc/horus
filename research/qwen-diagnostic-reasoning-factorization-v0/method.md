## Four arms and model-visible schemas

Exact schemas are frozen in schemas.json.

O — OPERATIONAL_COMPUTATION: only the operational rule and the world's two literal operand bundles, in fixed order. Return {"results":["result for first","result for second"]}. The specified output convention is exact: decimal integers as strings; Boolean outputs 0/1; state names as given; reachability as five bits; coefficient/window vectors comma-separated without spaces; transformed strings verbatim. No current/deployment/provenance/target fields, records, diagnostic classes, observed failures or evidence-sufficiency question. Two candidate computations are part of the declared diagnostic domain, not unrelated arithmetic padding. O's results are never fed into another call.

S — EVIDENCE_STATE_REASONING: authored raw evidence plus supplied required-output table for EVERY operand record, including distractors. No arithmetic requested. No final class names/definitions or classification field. Return exactly nine state fields: target_component_id; in_service_build_id; in_service_receipt_ids; other_build_receipt_ids (target only); other_component_receipt_ids; receipt_source_links; capture_groups; source_knowledge; conflicting_capture_ids. Receipt/source links cover all receipts. Capture groups cover all source declarations sharing one immutable capture ID. source_knowledge includes one row per capture: KNOWN when all declarations agree on one concrete input reference; UNKNOWN when every declaration is UNKNOWN; DISAGREEING when distinct concrete input references are asserted for the same immutable capture. input_ids lists the unique concrete references (empty for UNKNOWN). conflicting_capture_ids contains exactly DISAGREEING capture IDs. Thus conflict detection is legitimately a requested S output, never an S input flag or an R input conclusion. No free-form rationale rescues incorrect fields. Scope matters: other_build_receipt_ids excludes other components' receipts.

R — EPISTEMIC_REDUCTION: a separately authored aligned state constructed directly from the frozen world facts, NOT from S outputs, raw parsing or the existing compiler. No opaque record, component or capture IDs. The target has already been selected, and the two target trials are explicitly marked in_service true/false with creation order. For each trial provide its observed result, a single immutable-capture scope with equal-standing input declarations, the literal claimed operand value (or UNKNOWN), and the supplied required result for each known claim. Also provide the two admissible completions and their mechanically required results. No compliance flags, conflict flags, validity flags, sufficiency flags, possible-benign/possible-defect flags, or class-like field names. The model must compare values, notice incompatible assertions about one immutable event, and determine what follows. Known and UNKNOWN cases have the same field shape and complete admissible table. No statement paraphrases the desired final class. Return only the five-class classification object.

E — END_TO_END_DIAGNOSIS: the raw package, unchanged, with the same natural-label definitions and minimal classification schema as R. Qwen must compute and bind before judging. No supplied mechanical table, aligned state, evidence compiler or preprocessing. Exactly one independent request, no stage chaining.

R/E ontology and order unchanged:
SUPPORTED_CURRENT_DEFECT: Available current evidence supports a specific active structural or mechanical defect and distinguishes it from materially plausible benign alternatives.
NO_SUPPORTED_DIAGNOSIS: The internally valid evidence is sufficient within the declared contract/input scope and supports no current defect. Unusual or undesirable behavior alone is insufficient.
INSUFFICIENT_EVIDENCE: The evidence is internally valid but a current defect and a materially plausible benign explanation remain observationally indistinguishable.
HISTORICAL_DEFECT_NOT_CURRENT: A defect is demonstrated for an older version, while supplied current mechanisms and observations show it is no longer active within the stated scope.
INVALID_OR_CONTRADICTORY_EVIDENCE: The supplied evidence package contains incompatible immutable, version, capture or provenance facts and cannot support a valid operational diagnosis.

Arm names, gold, world/family identifiers and difficulty labels are not in any model-visible task. Instructions necessarily differ by requested responsibility; this is the experimental manipulation, not covert arm leakage. Class ontology appears only in R/E. All arms use fresh contexts and private native separated reasoning; only final output is scored. Model-neutral task files preserve messages and schema independently of runtime.

## Frozen scoring and gates

Strict JSON rejects duplicate keys, nonfinite numbers, wrappers and trailing prose. Full arm schema required for primary credit. No repair, critic, free-form/hidden-reasoning rescue, retries or interpretation of intended answers. For S arrays, order is semantically irrelevant: recursively sort array members by canonical JSON solely during comparison; duplicates remain disallowed by schema. O result order is significant. R/E classes exact. A schema-invalid answer gets zero primary credit; field diagnostics are reported only on schema-valid S answers, not repaired fragments.

O: exact joint correctness of both results /20, individual result correctness /40, per-family joint /2 and result /4, schema validity. Error categories: strict parse failure; schema failure; reversed result order when reversed gold exactly matches; value mismatch otherwise. O gate: >=17/20 joint AND >=1/2 joint in every operation family. The demanding 85% requirement matches previous minimal-ontology thresholds while the family floor prevents success concentrated on a subset.

S: each of the nine fields exact /20, joint whole-state correctness /20, schema validity. Categories correspond to target binding, current deployment, target other-build partition, target/distractor separation, source links, immutable capture grouping, source knowledge/unknown detection and conflicting captures. S gate: >=17/20 joint AND >=18/20 in EVERY field. This tests a usable complete state plus 90% field reliability; partial correct fields do not rescue a wrong state. Structured output burden is inseparable from this operational S test; a failed gate does not by itself reveal an internal cognitive mechanism.

R: class accuracy /20, each class /4, schema validity, fixed-order 5x5 confusion matrix plus missing/invalid-label column. R competence gate: >=17/20 AND >=3/4 in EVERY class. Independently report U+T+X /12 with a >=10/12 epistemic-subset diagnostic, not an extra requirement for the main gate. The 17/20 and class-floor gate matches ontology-v0, preventing majority/current-defect-only success.

E: separately registered gate >=17/20 AND >=3/4 in EVERY class; class accuracy, per-class /4, schema validity, confusion matrix and same descriptive >=10/12 subset check. Identical numerical thresholds make the R/E matched comparison interpretable, without pooling them. No matched decisive pairs were designed; sensitivity metric NOT_APPLICABLE for R and E.

Each arm also reports simpler/composition-dependent /10 and classwise performance where meaningful, descriptive only. For matched worlds report exact O/S/R/E correctness, R/E recognized-class disagreement and primary accuracy difference. World-level association counts (overlapping, not causal partitions): O wrong and E wrong; O correct and S wrong; S correct and R wrong; all O/S/R correct and E wrong; E correct with any O/S/R wrong; at least two isolated stages wrong; each pair of stage errors.
