## Corrected authority boundary

Only one unambiguous allowed `selected_action` authorizes execution. The response must be a JSON object with exactly one string `selected_action` from the three currently allowed actions. A missing, repeated, conflicting, malformed, or disallowed action is `action_parse_status=INVALID`; no execution occurs. The existing one semantic action retry remains. After two invalid action responses, stop the run. Descriptive fields never change the parsed action.

`reason`, `evidence_source`, `reliance`, `claimed_status`, and `claimed_consequence` are non-authoritative descriptions. If all are present and well typed, `descriptive_status=COMPLETE`. Missing fields produce `INCOMPLETE_DESCRIPTIVE_OUTPUT`; present malformed fields produce `INVALID_DESCRIPTIVE_OUTPUT`. Missing content is not fabricated or normalized. The entire parsed response is preserved in the private call stream; the raw output and its SHA-256 remain private. A valid action executes immediately even if descriptions are incomplete; no retry occurs merely for better prose. Agent/grounded disagreement is inferred only from well-formed explicit claims, never from malformed text.

A scheduled self-review makes exactly one model call. If its JSON fails the nine-field review schema, has incorrect decision IDs, or has malformed confidence/support fields, record `review_status=INVALID_SELF_REVIEW`, preserve the raw response privately, and create no proposal. Do not retry, repair, infer absent fields, or modify the action policy. A valid review is `VALID_SELF_REVIEW`; a nonempty proposed change is labeled `NON_AUTHORITATIVE_SELF_PROPOSAL`, and the literal `NO_CHANGE_PROPOSED` remains a valid no-change result. The driver separately records the exact reviewed decision IDs from authenticated trajectory metadata; it never writes them into a malformed model-produced `SELF_REVIEW` object. Before/after checks enforce no change to event count, Memory checkpoint, state, or grounded assessments during either valid or invalid reviews.

For each executed decision, store `action_parse_status` separately from `descriptive_status` and its missing/malformed field lists. For each review, store `review_status` separately from `proposal_status`. No overall schema-valid flag collapses these distinctions. Raw model requests/responses, HMAC keys, signed streams, and databases remain in a separate local private archive; only sanitized summaries, hashes, and verdicts may enter a publishable branch.

The original observational questions and result classes remain descriptive. The independent review audit after the campaign may classify valid proposals as supported, partially supported, hindsight overfit, contradicted, untestable, or no change. Invalid reviews are not proposals and cannot be promoted. No self-modification, training, controller change, prompt adaptation, or decision-policy change is authorized.
