## Oracle and noninterference

Oracle values are generated by independently deep-copying the registered current external world for each action and calling that detached world's normal execute method once. They are not an aggregation, manually supplied target, learned evaluator or receipt. Each copy starts from the identical current world state. Detached evaluations never call the live receipt source, publish Memory, authorize a choice or mutate the live context. The registered outcome table above is checked only as an independent construction audit.

Live order: authenticate context; render/freeze all three Map requests; send ADVANCE, HOLD, RETREAT once each; fsync each raw response before strict parse and each parse before the next send; bind recorded real outputs through the unchanged interface; only then evaluate the three detached world outcomes. World execution is forbidden during Map requests and interface binding, and during Explorer calls. The oracle is not accessible to the Map collector, parser or prompt. Protected before/after snapshots must match.

All three mandatory Map calls are issued even if one output is malformed. They are recorded before interface binding. The unchanged interface retains its fail-fast INVALID_MAP behavior when fed those recorded responses; no partial view or Model-Map Explorer invocation follows. This does not retry a model call or modify interface-v0. Legacy interface evidence fields named synthetic_* count recorded-response binding invocations, not extra inference.

## Prompts and schemas

Map system, exactly:

> Predict the next externally realized outcome for the specified action using only the verified chronological outcomes shown. Reply with exactly one JSON object with exactly two fields: next_state must be an integer in {0,1,2,3}, and consequence must be an integer in {-1,0,1}. Do not include any other fields or explanation.

Map receives only state, opaque target_action, VERIFIED_CHRONOLOGICAL_HISTORY. Each authenticated row has epoch, transaction_id, surface_action, next_state, consequence. The unchanged historical parser rejects nonintegers, bools, duplicates, extra fields, prose, extraction and coercion. Invalid output has no retry/repair.

Explorer system, exactly:

> Choose the allowed action whose current Map prediction has the highest predicted consequence. Reply with exactly one allowed action and no explanation.

Explorer receives only state and three actions rows, each containing opaque action and map_prediction {next_state, consequence}. Strict historical opaque parser unchanged. No history, truth label, source identity, confidence, evidence count, averages, explanation or authority capability. Explorer is intentionally evidence-blind; history depths are private diagnostics.

Oracle Explorer gets the mechanically evaluated finite forecast view, without an oracle label. Permutation Explorer gets identical state, aliases, consequences and row order, with next_state in row i replaced by original row (i+1) mod 3. Model-Map Explorer gets the interface's exact three parsed model forecasts, unmodified. No measured choice executes or creates a receipt/Memory record.

## Fixed schedule and sampler

Within context: Map ADVANCE, HOLD, RETREAT; detached oracle after all parses; Oracle then Permutation on even zero-based context index, Permutation then Oracle on odd; ModelMap last only for a unique valid Map maximum.

The permutation control deliberately uses the specified different seed; behavioral changes cannot be attributed solely to next_state fields.

Stateless requests, no returned context/chat history/weight change. temperature .2, top_p .9, top_k 40, num_ctx 2048, repeat_penalty 1.1; num_predict 32 for Map, 16 for Explorer.

Mandatory: 144 Map +48 Oracle Explorer +48 permutation Explorer =240 calls. Conditional: up to48 ModelMap Explorer calls. Hard maximum288; no retry, replacement, extension or hidden tie-break. A tie slot is intentionally UNISSUED, not a missing call. Invalid Map likewise prevents its conditional Explorer. Transport ambiguity/integrity/storage failures stop without automatic reissue.

The conditional request's bytes depend on unseen model forecasts, so its exact schema, rendering code, seed and eligibility rule are frozen; its actual hash is fsynced before any conditional send. ## Interpretation and stop

This is bounded proposal decomposition in four known current-relation fixtures, not closed-loop behavior. No measured Explorer choice executes. Detached oracle forecasts are experimental values, not new truth authority. Small matched representations/seeds and shared weights do not establish independent error mechanisms or causal token bias. The different permutation seed limits causal attribution. Trusted single-process fixture/source/driver are not hostile-code isolation or cryptographic attestation.

All prior research results remain unchanged, particularly the temporal negative and both Explorer negatives. No general world modeling, temporal-pattern forecasting, policy/persistent/weight learning, RL, AGI or RSI claim. Stop after the one campaign, replay and preservation. No full loop, confidence fields, tie-policy change, prompt tuning, main/tag changes or push. The next separately authorized research decision depends on which stage actually fails.
