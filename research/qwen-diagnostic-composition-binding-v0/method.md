## Interface and runtime

1. SUPPORTED_CURRENT_DEFECT: Available current evidence supports a specific active structural or mechanical defect and distinguishes it from materially plausible benign alternatives.
2. NO_SUPPORTED_DIAGNOSIS: The internally valid evidence is sufficient within the declared contract/input scope and supports no current defect. Unusual or undesirable behavior alone is insufficient.
3. INSUFFICIENT_EVIDENCE: The evidence is internally valid but a current defect and a materially plausible benign explanation remain observationally indistinguishable.
4. HISTORICAL_DEFECT_NOT_CURRENT: A defect is demonstrated for an older version, while supplied current mechanisms and observations show it is no longer active within the stated scope.
5. INVALID_OR_CONTRADICTORY_EVIDENCE: The supplied evidence package contains incompatible immutable, version, capture or provenance facts and cannot support a valid operational diagnosis.

## Deterministic balanced schedule

Seed 384206917; hash sorting, no model-dependent or scorer-dependent scheduling. Ten chronological blocks of seven calls: five A calls (one from each class and one from each level) and two B endpoints (one pair). The first five blocks use the first core of each class, last five the second. Let c=class index 0..4, b=block index 0..9. Level is level_permutation[(b mod 5+c) mod 5], where level_permutation sorts 0..4 by SHA256(seed|level-order|level). Thus each core receives all five levels, with interleaving, not consecutive L0-L4. Within a block A calls are hash-sorted by block and unit ID.

B contrast-family order is a seed-hashed permutation of five families. Blocks 0..4 use first pairs, 5..9 second pairs, ensuring each family once per half. Pair A first iff (family_index+replicate) mod 2=0, so exactly five A-first and five B-first pairs. B positions (zero based within seven-call block) are [(0,3),(1,4),(2,5),(3,6),(4,0),(5,1),(6,2),(0,4),(1,5),(2,6)]; sort each pair of positions before placing endpoints. Position counts are three everywhere except position 3 with two. All contexts fresh; no answer is read into another request. Part B endpoint class totals implied by required families are H6 D6 U4 T2 X2; they cannot be equal without changing the requested design. Balance by family, endpoint order and block composition is explicit.
